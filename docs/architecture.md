# Architecture and current scope

One Python CLI owns schemas, archive inspection, compatibility checks, private
lesson ingestion and publication checks. Agents share AGENTS.md. CLAUDE.md
imports it; .agents/skills is the canonical skill source and the Claude copy is
generated by tools/sync_skills.py. No cloud or model SDK is required locally.

The first slice implements specification validation, profile compatibility,
read-only archive checks, private corpus indexing, bounded candidate memory,
controlled publication exports and structured GitHub issue tools. Local tests
use synthetic archives created in temporary directories, not personal missions.

An archive PASS checks ZIP integrity, member safety, the mission table marker,
theatre identification and resource references. This is deliberately narrower
than Lua parsing or DCS semantics. Unknown mission fields are never rewritten.
Lua syntax checking requires an explicitly named Lua 5.1 compiler and never
executes the script. Missing tools report BLOCKED, not PASS.

Future slices: preserve-and-build backend, mission instrumentation and stable
run/checkpoint schemas, server-ops adapter, OVH lease/warmup/watchdog, client
multiplayer/SRS checks, integration contracts, lesson promotion/retrieval and
retention. None is silently simulated as successful in v0.1.

Dependency catalog support is declared by a profile, not a claim to support
every mod automatically. Runtime observations must identify the actual artifact,
run and dependency versions. A runtime controller must batch work to amortize
warmup and preserve server sessions it did not start.

Candidate ingestion validates, caps records and deduplicates exact content plus
context. It forces private/candidate classification even for approved inputs.
Conflicting IDs are rejected. v0.1 performs budget checks without automatic
deletion, semantic deduplication, expiry or promotion. Those need evidence and
policies in the next memory slice.
